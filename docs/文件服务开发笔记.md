## 🏗️ 预期架构

### 文件服务架构图
```
File Service Architecture
├── Controller Layer
│   ├── FileController (上传/下载/管理)
│   ├── VersionController (版本管理)
│   └── PermissionController (权限管理)
├── Service Layer
│   ├── FileService (文件业务逻辑)
│   ├── VersionService (版本控制)
│   ├── StorageService (存储管理)
│   └── PermissionService (权限验证)
├── Repository Layer
│   ├── FileRepository (文件元数据)
│   ├── VersionRepository (版本历史)
│   └── PermissionRepository (权限记录)
└── Storage Layer
    ├── Local File System (文件存储)
    ├── MySQL Database (元数据)
    └── Cache Layer (Redis缓存)
```

### 数据库设计
```sql
-- 文件表
files (
  id, project_id, name, path, size, 
  mime_type, hash, created_by, 
  created_at, updated_at, deleted_at
)

-- 文件版本表  
file_versions (
  id, file_id, version, path, size,
  hash, created_by, created_at, comment
)

-- 文件权限表
file_permissions (
  id, file_id, user_id, permission,
  granted_by, granted_at
)
```

### API接口设计
- **POST** `/api/v1/files/upload` - 文件上传
- **GET** `/api/v1/files/{id}/download` - 文件下载  
- **GET** `/api/v1/projects/{id}/files` - 项目文件列表
- **PUT** `/api/v1/files/{id}` - 文件信息更新
- **DELETE** `/api/v1/files/{id}` - 文件删除
- **GET** `/api/v1/files/{id}/versions` - 文件版本历史
- **POST** `/api/v1/files/{id}/versions` - 创建新版本
